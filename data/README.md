# Datasets

Nothing in this directory is committed except this file.

Three reasons, recorded here because the decision cost a day in Week 3
and should not be revisited from memory:

1. The Salminen CSV exceeds GitHub's 100 MB per-file limit, so the push
   is rejected outright.
2. Git LFS was evaluated and rejected — the free storage quota is small
   and both corpora are publicly downloadable, so paying storage to
   duplicate them buys nothing.
3. Redistributing someone else's research corpus inside a coursework
   repository is a licensing question nobody needs.

Instead, this file records where each file came from and what it should
hash to, and `python -m frd.download` reproduces the directory.

## Files

### `deceptive-opinion.csv`

- **Corpus** — Ott, M., Choi, Y., Cardie, C. and Hancock, J.T. (2011)
  *Finding Deceptive Opinion Spam by Any Stretch of the Imagination*,
  ACL 2011.
- **Contents** — 1,600 hotel reviews: 800 truthful, 800 crowdsourced
  deceptive. The deceptive half is human-written.
- **Source** — <https://www.kaggle.com/datasets/rtatman/deceptive-opinion-spam-corpus>
- **Automated?** No. Kaggle requires a signed-in account, so
  `frd.download` prints instructions instead of failing with a network
  error. Save the CSV here under exactly this filename.
- **Columns used** — `text`, `deceptive` (value `deceptive` means fake).
- **Downloaded** — _record the date when you download it_
- **SHA-256** — _record the checksum, then add it to `frd/download.py`_

### `fake_reviews_dataset.csv`

- **Corpus** — Salminen, J., Kandpal, C., Kamel, A.M., Jung, S. and
  Jansen, B.J. (2022) *Creating and detecting fake reviews of online
  products*, Journal of Retailing and Consumer Services, 64.
- **Contents** — real and machine-generated product reviews across
  several Amazon categories. The fake half is model-generated, which is
  what makes it the counterpart to the Ott corpus.
- **Source** — <https://osf.io/tyue9/>
- **Automated?** Yes, `make data` fetches it.
- **Columns used** — `text_`, `label` (value `CG` means computer
  generated).
- **Downloaded** — _record the date_
- **SHA-256** — _record the checksum, then add it to `frd/download.py`_

### `synthetic_human.csv`, `synthetic_machine.csv`

Generated by `python -m frd.make_synthetic`. **Not research data.** They
exist so the pipeline runs with no downloads — in CI, on a fresh clone,
and on screen in the D2 video. They are separable almost perfectly,
which the real corpora are not, so any number produced from them is a
smoke test and belongs in no report. `frd.datasets` tags them
`synthetic_*` in the `source` column so they can never be mistaken for
real results in `results.csv`.

A 60-row sample of each is committed to `tests/fixtures/` — small enough
to version, and the reason the test suite needs no network.

## Verifying what you have

```bash
python -m frd.download --verify
```

Prints the SHA-256 of every dataset present. Record these in this file
the first time, then anyone can check they are working from the same
bytes you were.
